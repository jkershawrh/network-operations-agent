= Evidence-Backed Network Operations Lab
:imagesdir: ../assets/images
:toc:
:toc-placement: preamble
:icons: font

AI can help a network operations center correlate alarms, consult diagnostic systems, and explain a likely cause. The difficult part is not generating an answer. The difficult part is proving which statements came from current systems, which came from previous incidents, what remains uncertain, and who is authorized to act.

This 90-minute lab teaches that distinction. You will inspect a working telco timing investigator, trace its evidence path, add a new diagnostic domain, build a synthetic incident, inject failures, and produce a qualification report that a NOC lead can review.

== The mission

A timing alarm has moved a simulated radio site into holdover. Existing checks can distinguish an OpenShift platform fault from a NIC timestamp fault, but they cannot prove whether the upstream grandmaster clock is unhealthy. Your job is to extend the evidence path without giving the agent permission to remediate the network.

You will use Red Hat OpenShift as the operational surface, an MCP-compatible read-only diagnostics service, and an optional OpenAI-compatible model endpoint. Model wording never overrides deterministic policy or evidence requirements.

You are acting as the platform engineer supporting a NOC reliability review. At the end, you must hand an operator evidence that answers three questions:

. What do the current diagnostic systems actually show?
. Why did the application select—or refuse to select—a cause?
. What is the safest next step for a qualified human?

== Outcomes

By the end you will have:

* A third, learner-authored synthetic incident pack.
* A contract for an upstream-clock MCP diagnostic.
* A reliability profile exercised against controlled failures.
* A machine-readable qualification report.
* A NOC decision brief that separates facts, history, inference, and unknowns.

== Audience

This lab is intended for technical sellers, solution architects, platform engineers, AI practitioners, and network operations engineers. You do not need to be a telecommunications timing expert. The exercises explain the relevant PTP and holdover vocabulary before you use it.

You should be comfortable reading JSON and running commands in a terminal. Familiarity with containers and Kubernetes is helpful, but every OpenShift command used in the lab is explained.

== Prerequisites

The ordered environment provides:

* A participant-scoped OpenShift namespace and terminal authenticated as the lab user.
* The network operations application and read-only MCP diagnostics service.
* A Route for the application API.
* `oc`, `curl`, `jq`, and standard shell utilities.
* Lab mode enabled for bounded synthetic scenario authoring and failure qualification.
* Optional CPU-hosted model access supplied by the environment. Model credentials are never displayed in the guide.

No cluster-administrator access, customer network access, real alarms, or remediation credentials are required.

== How the lab is organized

The journey builds in four phases:

[cols="1,2,3",options="header"]
|===
|Phase |Modules |What changes

|Understand
|Orientation, Modules 1–2
|Establish the healthy baseline and learn how evidence crosses trust boundaries.

|Build
|Modules 3–4
|Author a third incident and understand the new MCP diagnostic contract.

|Break and prove
|Modules 5–6
|Introduce controlled failures and turn expected behavior into repeatable qualification evidence.

|Communicate
|Module 7
|Package the result as a bounded NOC decision brief.
|===

Each module begins with learning objectives, explains why the exercise matters, and ends with a checkpoint. Do not skip the checkpoints: later exercises assume that the previous safety invariant passed.

== Estimated time

Plan for 75–90 minutes. The baseline and architecture modules take approximately 25 minutes, building the new scenario and tool contract takes 25 minutes, and failure qualification plus the decision brief takes 30–40 minutes.

[IMPORTANT]
====
All incidents are synthetic. No exercise performs remediation. Human approval is always required, and `action_executed` must remain `false`.
====
